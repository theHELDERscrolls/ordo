# Changelog

All notable changes to Ordo are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and the project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- npm workspaces monorepo (`shared`, `backend`, `frontend`) with a single root lockfile.
- `@ordo/shared` contract package (Zod) consumed by `backend` and `frontend`, wired with TypeScript project references so a contract change breaks compilation on both sides.
- Backend foundation: Express, Mongoose, CORS, Zod; compiled build (`tsc` to `dist`, `node dist`), `tsx` dev runner, ESLint flat config, `.env.example`, and a `/health` endpoint.
- Frontend foundation: Tailwind v4 (Vite plugin), React Router, React Query, React Hook Form, lucide-react.
- Shared tooling: root Prettier config (with Tailwind class sorting), Vitest per package.
- CI jobs (install, lint, typecheck, build, test) and a consolidated root Dependabot npm entry.
- Authentication: `POST /auth/login` issuing a JWT, Bearer-guarded routes with a sample `GET /auth/me`, and a development bootstrap seed.
- Domain data layer: Mongoose models for `Business` (with embedded branding) and `User`, mirroring the shared Zod contracts.
- Login UI: login page (React Hook Form + Zod), session context (`useReducer`/`useContext`), protected routing, and per-tenant white-label theming with a persistent light/dark toggle.
- Domain-oriented layout: backend `modules/`, frontend `core`/`features`/`shared`, and a `@` path alias on the frontend.
- Project documentation: a living `docs/` (index, architecture guide, and an `api/` reference with request/response JSON per endpoint) and a Getting started section in the root README.
- Inventory backend: `Product` domain (Zod contract, Mongoose model with a per-business unique SKU and a derived `stockStatus`), role-aware CRUD API with search/filter/sort/pagination, and a `GET /dashboard/stats` snapshot. `employee` is read-only; `admin` manages.
- Developer tooling: a `ship-pr` skill (`/ship-pr`) that automates the git-flow — logical commit split, CHANGELOG/version check, and a PR from the template.
- Inventory & settings UI: the inventory screen (debounced search, faceted category/supplier filters, stock-status chips, sortable columns with direction, pagination), a product create/edit form with a custom confirmation dialog, a read-only view for `employee`, a Settings section (theme, language, business, log out), the navigation shell, and reusable UI (`Button`, `Select`, `ConfirmDialog`, `RowLink`, `StockBadge`). Space Grotesk display font via CSS.
- Inventory facets endpoint (`GET /products/facets`) for filter values, plus a wider auto-parts seed with an `employee` user.
- Dashboard panel: four stat cards (product count, inventory value, low stock, out of stock) reading `GET /dashboard/stats`, with the stock cards deep-linking into the inventory pre-filtered by that status. The inventory's stock filter now lives in the URL (`?stockStatus=low|out`) so it can be linked to.
- Inventory value breakdown endpoint (`GET /dashboard/inventory-breakdown`): value and product count per category, plus the products ranked by value, all from a single `$facet` aggregation.
- Two panel charts built on Recharts: capital by category (ranked horizontal bars, tail folded into "Otras") and capital concentration (running share of value across the ranked products, on one axis, with the 80% ABC reference line). Both are single-series and monochrome, coloured from the theme tokens so they follow the light/dark toggle. Recharts is isolated in a lazily loaded chunk so it stays out of the entry bundle.
- Reusable `StatCard`: a container-query card whose figure scales with the card's own width, so the same component fits two columns on a phone and four on a tablet.
- Product detail dialog: a row now opens the product's read-only sheet — stock as the headline figure, prices, reorder point, category, supplier and description — with Edit and Delete for `admin` only. The open product lives in the URL (`?product=<id>`), so a sheet is linkable and the phone's back button closes it.
- `Modal`, the app's base modal, built on the native `<dialog>`: `showModal()` supplies the focus trap, Escape, the top layer and an inert, unscrollable background, so the component only adds the shape — a sheet rising from the bottom edge on a phone, a centred panel from `sm` up — and an entrance that slides in on `translate` alone. Closing is immediate.

- Ordo has a mark: a thick ring holding three bars of decreasing length, the letter O of the name and a shelf read head on. It ships as `favicon.svg`, four shapes and no raster, which carries its colour in `currentColor` and swaps it on `prefers-color-scheme` — so the tab icon inverts with the theme exactly as the interface does — plus a 180px `apple-touch-icon.png`, the one place iOS refuses an SVG. The accent stays out of it: the mark is Ordo's, not the tenant's.
- The document head, which until now was Vite's scaffolding: the real title and description, `lang="es"` for the language the interface actually speaks, and `theme-color` in both schemes so the browser's own chrome follows the app's background. Open Graph covers the link pasted into a chat, without `og:url` or `og:image` — both need an absolute URL and there is no domain yet. `robots: noindex, nofollow`, because there is no public signup and every screen sits behind the login: the only thing a crawler could index is a business's sign-in page.
- Design specs live in `docs/specs/`, written before the work starts. The first one covers the stock movement ledger and the CSV import/export path.
- Stock ledger API: `GET /movements` (the business's history newest first, filtered by product, type and date range, paginated, with the product's name and SKU and the author's name resolved server-side) and `POST /movements` for an entry or an exit. Recording is the one write open to `employee` as well as `admin`, against the app's usual split: the person behind the counter is who moves the stock, and a sale that waits for the owner to type it is a sale that goes unrecorded, which defeats the point of keeping a ledger. It is safe in more hands than the catalogue precisely because it is append-only — an employee adds to the trail and cannot rewrite it, and every entry carries who made it — while prices, reorder points, creating and deleting products and the CSV import all stay `admin`. An exit is a single atomic update guarded by the stock available, so it returns `409` and changes nothing rather than driving the stock negative, and two concurrent exits cannot both pass the check. There is no update and no delete: a mistake is corrected with an opposing movement.
- Every other write that touches stock now leaves its own movement: creating a product with stock records an `in` ("Stock inicial"), changing the stock in the product form records an `adjust` with the size of the correction, and deleting a product deletes its history with it.
- Stock movement ledger: a `StockMovement` model (`in`/`out`/`adjust`, an unsigned quantity, the `resultingStock` it left behind, the reason, and who did it), indexed for the business history and for a product's own sheet. Append-only, so it has a creation date and no update date. The API and the UI come in the next phases.
- Inventory CSV export (`GET /products/export.csv`): the catalogue as a spreadsheet, honouring the list's own filters and sort and ignoring its pagination, so what you export is what you are looking at. Both handlers now share `buildProductFilter` and `buildProductSort` rather than restating them. The file is written the way a Spanish Excel expects it — `;` between fields, `22,8` for the decimals, and the UTF-8 BOM without which the accents arrive as mojibake — so it opens in columns on a double click instead of through the import wizard.
- Inventory CSV import (`POST /products/import`, `admin`): the file goes in raw as `text/csv` and upserts on `(businessId, sku)`, the pair the unique index already enforces. Only the columns the file fills are written, so a `sku,name` file renames products without flattening their prices; `quantityMode=set` writes the `stock` column as the new stock and records an `adjust`, `add` adds it and records an `in` of the increment, both with reason "Importación CSV". An invalid row is reported with its line number and skipped without aborting the file, two rows for one SKU are refused (the second would be computed from a stock the first has already moved), and `dryRun` — the default — reports exactly what the real run would then do without writing anything. An exported file re-imports as a no-op.
- CSV read/write in `backend/src/lib/csv.ts` with no dependency: quoted fields, `""` escapes, delimiters and newlines inside quotes, `CRLF`, the BOM Excel writes, and blank lines, plus tests for each of those and a round trip.
- Movements section (`/movements`), a third entry in the navigation beside the panel and the inventory: the history newest first with the product, the type, the quantity signed by that type, the stock it left behind, the reason, who did it and how long ago. Its filters — product, type and date range — live in the URL like the inventory's, so a filtered view is shareable and the product sheet can link straight into one product's history; the table folds into cards below `md`, and the mobile bottom bar picks the section up on its own.
- "Registrar movimiento" dialog: product, entry or exit, quantity and an optional reason. Only `in` and `out` are offered, mirroring the API — an `adjust` is written by the system when a correction arrives through another path, never declared by a client. A refused exit comes back as "No hay stock suficiente" rather than as the API's own wording, and the movement invalidates the ledger, the inventory list, the product's sheet and the panel's figures, so the stock updates everywhere without a reload.
- `ProductPicker`, the search field that stands in for a product dropdown: the catalogue runs past what the list endpoint returns in one page, so the options cannot be loaded up front. It queries the API as you type and holds the choice as an id, which is what lets the filter survive a reload and a shared URL. Both the ledger's filter and the register dialog use it.
- "Últimos movimientos" at the foot of the product sheet: the last five for that product with a link to the rest, so the stock figure at the top of the sheet is explained where it is read.
- Relative dates (`relativeTime` in `shared/format.ts`) on `Intl.RelativeTimeFormat`, with the exact timestamp as the element's `title`. A history is read for how recent an entry is, not for which Tuesday it landed on, and the native formatter means no phrasing table and no date library.
- "Exportar CSV" in the inventory header, for any role: downloads the catalogue as it is filtered on screen, pagination aside. It goes through `fetch` and a `Blob` rather than a link to the URL, because a plain `<a href>` cannot carry the Bearer token, and it takes its filename from the `Content-Disposition` the API sends so the name stays defined in one place.
- "Importar CSV" and its dialog, for `admin`: picking a file reads it with the native `file.text()` and asks the API what it would do with it, choosing between replacing the stock or adding to it asks again, and nothing is written until "Importar" repeats the same request without the dry run. The preview reports how many products would be created, updated and skipped, with the failing rows in a scrollable table that names the line to fix in the spreadsheet. The report renders from a `useDeferredValue` copy with its figures in a `useMemo`, so a hundred-row error list does not lock the dialog while it paints. A real import refreshes the list, the product sheets, the filters' categories and suppliers, the ledger and the panel without a reload.
- `apiDownload` in the API client, for a file the token guards, alongside `apiFetch`; `apiFetch` now only sets the JSON content type when the caller has not set one, which is what lets the import send the file as `text/csv`.
- Deployment runbook (`docs/deployment.md`): the database on MongoDB Atlas, the API on Render and the web client on Vercel, in the order their configuration depends on each other, with the settings each host is given and why. Neither host needs a step for `@ordo/shared`, since the project references build the contracts on the way to whatever imports them. The README notes the free tier's cold start — a Render service spins down after 15 minutes and takes about a minute to wake — rather than burning the monthly hours on a pinger to hide it.
- `CORS_ORIGIN`, a comma-separated list of the origins allowed to call the API. Unset it allows any, which is what local development and a REST client want; in production it names the deployed frontend. A list rather than a single value, so a custom domain is added beside the `.vercel.app` one instead of replacing it.
- `frontend/vercel.json`, rewriting every unmatched path to `index.html`: the routes are the client's, so without it a reload on `/movements` asks the host for a file that does not exist and gets a 404.

### Changed

- `parseCsv` no longer assumes the comma: it detects the field delimiter from the header, and the product import reads `22,8` as it reads `22.8`. "CSV out of Excel" is not one format — Excel writes the list separator of the machine's locale, so the same spreadsheet arrives comma-separated from an English computer and semicolon-separated from a Spanish one, where the comma is already holding the decimals. Assuming one convention read a Spanish file as a single column with every price `NaN`. A number carrying both marks (`1.234,56`) stays ambiguous without a locale the file does not carry, so it is reported by line rather than guessed at.
- Product images are out of scope: `imageUrl` is gone from the contract, the model and the detail dialog, and the Cloudinary/S3 mentions with it. Storage was optional and the app has no use for it that justifies the surface. The Telegram bot is dropped for the same reason: the inventory's own filters already answer what it would have answered.
- Tapping a product no longer jumps into the edit form: it opens the detail dialog, and it does so for `employee` too, which until now had no way to see a product's detail at all. Deleting moved out of the product form's header and into that dialog, leaving a single place to delete from, `ConfirmDialog` is rebuilt on `Modal`, and `RowLink` goes with its last caller. Saving the product form now returns to that product's sheet rather than to the bare list, so a change lands in view; a create ends on the product it just made.
- Root README now reflects the real state: current project status and the actual monorepo layout. Replaced the default Vite boilerplate in `frontend/README.md` with a real one.
- Aligned the versioning policy in `CLAUDE.md` (no version bump on `develop`; bump, seal and tag only at release).
- ESLint configs set `tsconfigRootDir` to disambiguate the monorepo TSConfig root; `PATCH /products` uses `returnDocument: 'after'` (Mongoose 9 deprecation).
- Documentation pass over the whole codebase: prose comments condensed and rewritten as TSDoc on the exported symbols (contracts, hooks, components, middleware, routes), leaving inline comments only where they explain a decision that has no exported symbol to hang from.
- The dashboard's charting layer moved into `features/dashboard/charts/`, so the folder boundary matches the lazily loaded Recharts chunk boundary.
- The reorder threshold now lives only in `product.status.ts`, as a predicate for loaded documents and a matching MongoDB expression for queries. The model's `stockStatus` virtual, the inventory's stock filter and the panel's low/out counts all read it instead of restating it, and a test evaluates the two encodings against each other so they cannot drift.
- The backend's `npm test` no longer runs the compiled copies of the tests in `dist/`. After a build every test was being executed twice, once against JavaScript that a later edit could leave stale, which reported 38 tests where there are 19. The test files are still typechecked, since they stay in the build.
- The Node version is declared once, as `engines.node` in the three manifests, and CI reads it from there (`node-version-file`) instead of pinning its own copy. Render and Vercel honour the same field, so the runtime cannot drift from the one the pipeline tests on.
- The seed no longer holds the catalogue as TypeScript literals: it reads `backend/seed/*.csv` with `node:fs` and resolves the natural keys (`slug`, `email`, `sku`) to ObjectIds. The demo data grew with it, from 45 products to 132 plus 218 movements, and each product's stock is now the result of replaying its own ledger from an opening balance rather than a number typed into the file.
- CORS exposes `Content-Disposition`. It is not one of the headers a browser hands to cross-origin JavaScript by default, so without it the CSV export could not read the filename the server sends and would have to invent one, in a second place that can drift from the first.
- Movement badges are told apart by colour and not only by their word: an entry green, an exit red, an adjustment blue, each a tenth-opacity tint with a matching border and the text a step darker in light mode and lighter in dark. A ledger is read down a column for direction, which the word alone made slow. The hues are fixed rather than the tenant accent — which already means "agotado", and which for a business with a green accent would paint every exit as an entry — and amber stays reserved for "stock bajo".
- The README no longer describes the project as an authentication slice with the inventory still to come: the catalogue, the ledger and the CSV path are all in place, and deployment is what is left.
- The page frame is a component and two tokens rather than a class list repeated on every screen. `Page` applies `--spacing-page-x` and `--spacing-page-y` and picks one of three max widths, `PageHeader` carries the title, the description and the screen's actions, and the five screens state none of it themselves: the app's margins now move from two lines of `index.css`.
- What the inventory and the ledger were both writing by hand is now written once. `FilterChips` is the row of pills, `ListState` the centred block a list falls back to while it loads, when it fails and when it is empty, `tableHeadClasses` the header row both tables share, and `fieldClasses` the chassis behind every input, date bound and the dropdown's own button — resolving the valid/invalid border inside the helper, since which of the two wins would otherwise depend on the order Tailwind emits them in rather than on the order they are written. Two hooks follow: `useUrlParams`, which keeps a list's filters in the query string and takes every key in one call so two writes in a tick cannot undo each other, and `usePage`, which returns to the first page when those filters change. `toQuery` moved to the API client, where the ledger now shares the copy the catalogue and the CSV export were already using instead of restating the loop.
- The architecture guide is a guide to the structure again, with each domain in its own document under `docs/domains/`: tenancy and authentication (including the role table the split was only implied by), the inventory, the stock movements, the CSV path with the seed built on it, and the dashboard panel. Nothing was rewritten in the move; what grew is the frontend section, which now describes the styling tokens and the shared pieces above.

### Fixed

- `PATCH /products/:id` with a subset of fields silently reset `stock`, `minStock` and `costPrice` to zero. Zod carries a `.default()` through `.partial()`, so `updateProductSchema`, built from the creation schema, filled in the three defaulted numbers on every partial update. The frontend form always submits every field, which is why it never surfaced. The update schema is now built from the editable fields without the defaults, and a test pins the behaviour.
- "Nuevo producto" and "Registrar movimiento" overflowed the header on a narrow phone: both keep their label from `sm` up and shrink to their `+` below it, named for a screen reader by their `aria-label`, and the header wraps instead of pushing its actions off screen.
- The pager broke apart on a narrow phone, squeezing its counter into one word per line beside the buttons. It now stacks below `sm` and lines up again from there, its two steps are arrows on a phone and words from `sm` up, and the two copies of it — the inventory's and the ledger's, identical down to the class list — are one `Pagination` component.
- The type badges in the product sheet's "Últimos movimientos" left no room for the reason on a narrow phone. They keep the icon alone below `sm`, with the word in the accessibility tree and back on screen from `sm` up. Only that list is compact: the ledger's own rows and the register dialog's type selector keep their labels, where the word is what is being read or chosen.
- The README asked for Node 20 while `engines.node` pins 24, so a fresh clone followed the README straight into an `EBADENGINE` on install. It now states the version the manifests declare and where CI, Render and Vercel read it from, and lists the seed's `employee` credentials beside the admin's, since the role split cannot be tried with one account.
- The OpenAPI contract contradicted the API on `PATCH /products/{id}`: its body was an `allOf` over `ProductInput`, which carries `required: [name, sku, unit]`, so a validator would refuse exactly the partial update the endpoint exists for. It now has its own `ProductPatch` schema, with nothing required and no defaults, and the `Product` schema declares the `createdAt` and `updatedAt` the API has always returned.
- `GET /products` and `GET /movements` document their paging bounds — from page 1, 20 rows by default and 100 at most, clamped rather than refused — and the API index lists the facets endpoint, which was documented in full but missing from the table that leads to it.
- The dashboard and ledger examples were invented figures that disagreed with each other about the size of the catalogue. They are now what the seed data actually produces, replayed from the CSV files: 132 products worth 25177.8, 17 low and 4 out, and 337 movements once the opening balances are counted.
- A fresh clone could not be seeded by following the README: `@ordo/shared` is consumed as a built package through its `exports`, its `dist` is not committed, and nothing builds it on install, so `npm run seed` died on `ERR_MODULE_NOT_FOUND` before reaching the database. The README now builds the contracts before seeding, and says why it is a once-per-clone step.
- `CONTRIBUTING.md` still promised setup instructions "as the backend and frontend packages are added", both of which shipped months ago. It points at the README for them and states the checks CI runs and the CHANGELOG policy instead.
- Building the frontend on its own from a clean tree failed with `Cannot find module '@ordo/shared'`. The dependency was declared on the solution file, where it is only a build order, and `tsconfig.app.json` — the project that actually holds the code importing it — was listed first, so it was typechecked before the declarations it reads existed. It now declares the reference itself. Nothing caught it because the root `npm run build` walks the workspaces in order and builds the contracts first; a host pointed at `frontend/` does not.
